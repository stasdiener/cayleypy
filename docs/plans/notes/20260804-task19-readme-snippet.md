## 2. Сниппет README: как проверялся

Сниппет («конфиг → обучение → чекпойнт → Bellman-дообучение → ансамбль → beam») проверен в два прохода:

1. **Полный бюджет** — скрипт, содержащий сниппет дословно, прогнан целиком: претрейн 200 эпох (лосс 902 → **248.23**,
   т.е. воспроизводит рецепт PR11 из `20260804-task12-demo-checkpoint.md` бит-в-бит), Bellman-дообучение 100 эпох
   (лосс 5.95 → 1.57), затем загрузка обоих чекпойнтов, ансамбль и луч: `Path found: True length: 44`.
2. **Дословный ре-прогон текста README** — блок вырезан из README регуляркой и исполнен как есть с урезанным бюджетом
   (3 и 2 эпохи, 32 волка): выполняется до конца, exit 0 (пути, естественно, не находит — модель не обучена). Это
   проверка того, что в README попал исполнимый код, а не то, что было в черновике скрипта.

## 3. Замеры, на которые ссылается текст под сниппетом

50 равномерно случайных перестановок 14 элементов (`torch.manual_seed(11)`, `torch.randperm(14)`), `lrx-14`
(диаметр 91), `use_child_scores=True`, `non_backtracking=True`, `max_steps=1000`, CPU. Каждый найденный путь
провалидирован `apply_path` (приводит в центральное состояние).

| Луч | walks only | bellman only | ансамбль 0.3/0.7 | ансамбль 0.5/0.5 |
|---|---|---|---|---|
| 30 | 41/50 (66.7) | 41/50 (67.2) | 44/50 (68.0) | 45/50 (69.0) |
| 100 | 47/50 (64.6) | **49/50 (63.2)** | **50/50 (63.4)** | 49/50 (62.7) |
| 300 | 50/50 (62.2) | 50/50 (62.0) | 50/50 (61.5) | 50/50 (61.7) |

В скобках — средняя длина найденного пути. Выводы, которые попали в README (и только они):

- при луче 100 ансамбль решает все 50, дообученный чекпойнт — 49, обученный на волках — 47;
- при луче 300 все три решают все 50;
- хэмминг — 0/50 даже при луче 1000 (замер PR11, не перепроверялся).

Чего в README сознательно **нет**: при луче 1000 разницы между тремя предикторами не видно (все решают всё), поэтому
сниппет использует луч 100 — иначе цифры рядом с ним были бы бессодержательны. Эффект ансамбля здесь скромнее
«×2 к ширине луча» из описания PR7: `lrx-14` для этой модели слишком лёгкий, разница живёт только на узких лучах.

## 4. CLAUDE.md

Живёт **только на ветке `plan`**, вместе с планом и заметками. Причина: ветки `feat/*` растут от `main` форка, и любой
файл в них попадает в диф будущего upstream-PR; процессная документация там неуместна. Содержимое — то, что стоило
времени в этой серии: карта ветвей и протокол стека PR, правила upstream (2 апрува, сброс апрува пушем, `format-check`
по всему репозиторию), ловушки 3.9/torch 2.8, и список фактов о коде (generator-major `get_neighbors`, identity-хэшер в
`get_unique_states`, плоские поля `ModelConfig`, опции луча только в `search_simple`, неизменность state_dict
`MlpModel`, баг пустого фронтира, V-голова `QVModel` без супервизии).
