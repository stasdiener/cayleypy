# Task 12 (PR11): демо-чекпойнт в PREDICTOR_MODELS — рецепт, замеры, пределы

PR: [stasdiener/cayleypy#11](https://github.com/stasdiener/cayleypy/pull/11), ветка `feat/demo-checkpoint`,
base `base/demo-checkpoint` (механический мерж `feat/train-data-sources` + `feat/resmlp-qmlp` + `feat/child-scored-beam`).

## 1. Почему нужна была merge-база из трёх ветвей

Q-модель (`n_outputs == n_generators`) **не работает** ни в одной ветке по отдельности:

- архитектуру с несколькими выходами даёт только PR3 (`feat/resmlp-qmlp`): в PR10 `MlpModel` падает на `n_outputs != 1`,
  `RESMLP` не зарегистрирован;
- в луче Q-модель используется только через `search_simple(use_child_scores=True)` из PR2 — без него `beam_search`
  зовёт `predictor(states)` на плоском наборе детей и получает 2-D выход → понятная ошибка из PR1, но не поиск;
- тренер и источники данных — PR9/PR10 (`feat/train-data-sources`).

Поэтому создана `base/demo-checkpoint` (как `base/trainer-core` в Task 10) — она же base PR, чтобы диф показывал только
изменения PR11. Полный прогон тестов на merge-базе перед началом работы: 398 passed / 35 skipped / 3 xfailed.

## 2. Рецепт (воспроизводимый, попал в README)

`lrx-14` (диаметр 91 = n(n−1)/2, 3 генератора L/R/X), `RESMLP` `[512,512,512]`, `n_outputs=3` → 630 787 параметров.

```
TrainConfig(n_epochs=200, n_walks=1024, rw_length=92, batch_size=1024,
            lr=1e-3, lr_min=1e-5, ema_decay=0.999,
            anchors_depth=6, anchors_fraction=0.02, seed=42)
```

Время: 167 с на CPU (M-серия, torch 2.13), лосс 902 → 248. Данные: `SparseQSampler` (classic-волки, размечены prev/next)
+ 2% `BfsAnchors` (точные метки, все 3 выхода) через `MixtureDataSource` — то, что трейнер собирает сам по конфигу.

Диаметры LRX(n) проверены точным BFS: n=6..11 → 15, 21, 28, 36, 45, 55, т.е. ровно `n(n−1)/2`; отсюда `rw_length`.

## 4. Где рецепт кончается (важно для PR16)

Тот же рецепт с бюджетом ×4 (400 эпох × 2048 волков, 1463 с):

| Граф | Диаметр | Луч 1000 | Луч 3000 | Луч 10000 |
|---|---|---|---|---|
| `lrx-14` (200 эпох × 1024) | 91 | 50/50 | — | — |
| `lrx-18` (200 эпох × 1024) | 153 | 19/20 | — | — |
| `lrx-20` (400 эпох × 2048) | 190 | 4–7/10 | 8/10 | 8/10 |

Диагноз: на `lrx-20` лосс выходит на плато ~820 уже к 5-й эпохе и дальше не двигается 395 эпох — **предел не бюджета, а
разметки**. Метка sparse-Q — индекс шага classic-волка (`p±1`), а classic-волк в LRX сильно возвращается (R = L⁻¹), так
что на больших `p` метка завышена в разы и превращается в шум. Отсюда два следствия:

- демо регистрируется для графа, где рецепт **надёжен** (критерий upstream — «reliably finds the paths»), а не для
  самого большого, где он «почти работает»;
- это ровно тот случай, для которого в плане есть PR16 (Bellman/DAVI: таргет `1 + min_a V_target(child)` не зависит от
  индекса шага волка) и `PathDataSource` из PR10 (hindsight-метки по найденным путям — тоже без индекса шага).
  Ожидание: после Bellman-дообучения `lrx-20` должен стать надёжным на луче 1000.

## 5. Скоуп-добавки PR11 (сверх плана)

- `ModelConfig.load` принимает **и** голый state_dict, **и** самоописывающий чекпойнт PR1 (детект по ключу
  `"state_dict"`) — иначе веса, записанные `Trainer.save`, нельзя положить в реестр без ручной конверсии.
- Ошибки скачивания с Kaggle обёрнуты (`RuntimeError` с именем модели и подсказкой про сеть/креды) — пункт плана
  «понятная ошибка при недоступности kagglehub».
- `Predictor.pretrained` сверяет `ModelConfig.graph_hash` с графом: модели ищутся **по имени графа**, а для Q-модели
  достаточно переставить генераторы, чтобы её выходы стали бессмысленными.
- Тесты в `models_test.py` (оба формата весов, ошибка скачивания) — файл не был в списке PR11, но `ModelConfig.load`
  живёт в `models.py`.

## 6. Kaggle

- Модель: [rokham/lrx-14-q](https://www.kaggle.com/models/rokham/lrx-14-q), variation `pyTorch/resmlp-512x3`,
  id для реестра `rokham/lrx-14-q/pyTorch/resmlp-512x3/1`, файл `lrx_14_q_resmlp.pt` (2.4 МБ).
- Лицензия MIT, модель **публичная** (`kagglehub.model_upload` создаёт приватную — публичность выставлена отдельным
  `ApiUpdateModelRequest` с `FieldMask(paths=["title","subtitle","description","is_private"])`).
- Анонимное скачивание проверено (`HOME` и `KAGGLEHUB_CACHE` в /tmp, без `KAGGLE_*`) — CI не нужны креды.
- Файл — самоописывающий чекпойнт PR1: внутри веса + `ModelConfig` + `graph_hash` графа.

## 7. Ловушки, на которые ушло время

- `kagglehub.model_upload` не умеет делать модель публичной; поле `update_mask` требует
  `google.protobuf.field_mask_pb2.FieldMask`, а не строку.
- `pgrep -f "python .../train_demo.py"` матчит сам себя, если строка есть в командной строке ожидающего шелла — ждать
  тренировку надо по PID.
- `pylint` в этом репо не отключает `broad-exception-caught`, поэтому ошибки kagglehub ловятся списком типов
  (`OSError` покрывает `KaggleApiHTTPError`, т.к. `requests.RequestException` — подкласс `IOError`).
